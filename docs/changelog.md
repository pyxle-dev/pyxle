# Changelog

Release notes for Pyxle. While we're in beta (`0.x`), minor versions may include breaking changes — those are called out explicitly here. To upgrade, run `pip install --upgrade pyxle-framework`.

## Unreleased

- **`error.pyxl` is now a client-side error boundary too.** The server already renders the nearest `error.pyxl` when a loader or the initial render fails; now that same boundary keeps working in the browser. If a component throws while re-rendering — after a state update, during a client-side navigation, or on a hydration fault — Pyxle catches it and renders the nearest `error.pyxl` in place, instead of React unmounting the page to a blank screen. The boundary receives the **same** `error` prop (`message`, `statusCode`, `type`) on both sides, so one `error.pyxl` renders identically wherever the fault happened. It is transparent until something throws (so hydration is byte-for-byte unchanged) and resets on the next navigation; the nearest `error.pyxl` is resolved per route (closest-ancestor walk-up) and threaded to the client like the streaming `loading.pyxl` boundary. In `pyxle dev` the error overlay still surfaces the full stack on top; in production the boundary is the user-facing fallback. This catches *render* faults — an error in an event handler or an `await` is handled where it occurs (a `try/catch`, or an `ActionError` from `useAction`). See [Error Handling → Client-side errors](guides/error-handling.md#client-side-errors).
- **Built-in rate limiting — `pyxle.middleware.RateLimitMiddleware`.** A dependency-free **token-bucket** limiter, enabled from `pyxle.config.json` with no code: `{"rateLimit": {"requests": 100, "window": 60}}`. Each client (keyed by remote IP, or the first `X-Forwarded-For` hop when `trustForwardedFor` is set behind a trusted proxy) gets a bucket of `requests` tokens that refills at `requests / window` per second — so a brief burst is allowed while the sustained rate is bounded, friendlier than a hard fixed window. Over-limit requests get `429 Too Many Requests` with a `Retry-After` header. `exemptPaths` skips health checks and metrics scrapes (segment-boundary matching, like `csrf.exemptPaths`). The limiter sits just inside request observability, so a throttled request still gets a correlation id and is counted, but is rejected before CSRF, static serving, or the handler do any work; the bucket store is bounded by an LRU cap so a flood of unique clients can't grow memory without bound. **Multi-worker caveat:** the store is in-memory and per-process, so under `pyxle serve --workers N` the effective global cap is `N × requests` — for one shared limit, rate-limit at your reverse proxy. Off by default (`requests: 0`). See [Middleware → Rate limiting](guides/middleware.md#rate-limiting) and [Security → Rate limiting](guides/security.md#rate-limiting).
- **Route policies now apply to `@action` endpoints.** Previously, a route hook registered under `routeMiddleware` wrapped page and API routes but **not** `@action` calls — so an auth or rate-limit policy could be silently bypassed by hitting the action endpoint directly. Actions now run through the same route-hook pipeline; register action policies under the new `routeMiddleware.actions` list. Because an action replies with JSON, an action hook should reject with a JSON `401`/`403` rather than an HTML redirect (which is why actions get their own list instead of inheriting the page's hooks). See [Middleware → Route-level hooks](guides/middleware.md#route-level-hooks).
- **`pyxle serve --workers 0` auto-detects the core count.** Multi-core serving (`pyxle serve --workers N`, each worker an independent process sharing one socket) already shipped; now `--workers 0` sizes the worker count to the host's CPU cores, so you don't hard-code it per machine. The [Deployment guide](guides/deployment.md#multi-core-worker-processes) gains a consolidated **per-worker state** table (which features are per-process — page cache, WebSocket pub/sub, metrics, background tasks — and the shared-backend escape hatch for each), **rolling-deploy / graceful-restart** guidance (blue-green via `/readyz`, systemd, and the gunicorn-preload option), and the rationale for the share-nothing, per-worker-SSR-pool design.
- **Build optimization: responsive `<Image>`, preload hints, and `--analyze`.** `<Image>` (from `pyxle/client`) is now an optimized image on par with Next.js's for everything that doesn't need a server-side optimizer: pass a `loader` (a CDN like Cloudinary/imgix, or a build plugin) and it emits a responsive `srcset` across a device-size ladder; it also gains `fill` mode, `sizes`, `quality`, `objectFit`, and `priority` → `fetchpriority="high"` for the LCP image — plus the existing blur placeholder, `fallbackSrc`, lazy-loading, and layout-shift prevention. Without a loader it stays a clean `<img>` (no fake srcset that re-downloads the full image — resizing needs a real backend, which stays opt-in). Separately, the SSR shell now injects `<link rel="modulepreload">` for each page's entry and the chunks it imports (from the build manifest's import graph), so they download in parallel with HTML parsing; `pyxle build --analyze` prints a dependency-free JS/CSS bundle-size report (raw + gzip); and the generated Vite config carries an explicit `build` block (faster builds — Vite's slow gzip-size reporting is off since `--analyze` covers it). JS/CSS minification, tree-shaking, and code-splitting were already on via Vite's production defaults. See [Build Optimization](guides/build-optimization.md).
- **Background tasks & deferred work.** Two ways to run work off the request's critical path. Inside an `@action`, `request.state.background.add_task(fn, *args)` (a Starlette `BackgroundTasks`) runs after the response is sent — ideal for "send the welcome email after signup"; returning `{"background": [fn, *args]}` is shorthand for a single such task. For fire-and-forget work from anywhere (loaders, actions, API routes), the new `pyxle.tasks.enqueue(fn, *args)` schedules it on a small **in-process** worker pool — coroutine functions are awaited, plain callables run in a thread, a failing task is logged (never takes a worker down), and the queue is bounded (`TaskQueueFull` under overload). The queue starts/stops with the app. **Multi-worker caveat:** it's per-process (like the in-process WebSocket broker), so for durability or cross-worker/exactly-once semantics, hand off to a real job queue — the guide documents Celery, ARQ, and Dramatiq integration. See [Background Tasks](guides/background-tasks.md).
- **OpenTelemetry tracing (opt-in).** Emit OpenTelemetry spans for each request plus child spans for the SSR render, `@server` loaders, and `@action` calls, so a slow page surfaces as a drill-down trace. It's the heaviest integration, so it's a **separate** optional extra (`pip install "pyxle-framework[observability-otel]"`) and **fully off** by default — with the extra absent, spans are a zero-cost no-op (one boolean check), and the exporter endpoint comes from the standard `OTEL_EXPORTER_OTLP_ENDPOINT` env var. Sampling defaults to 5%. A base Pyxle install pulls in no OpenTelemetry packages; enabling `observability.otel` without the extra fails loudly at startup. See [Observability → OpenTelemetry tracing](guides/observability.md#opentelemetry-tracing).
- **`pyxle dev --dashboard` — a live terminal observability panel.** Opt into a compact panel that refreshes every few seconds with request throughput and error rate, status-class breakdown, request/SSR-render/loader/action latency, and the page-cache hit ratio. It reads the same in-process metrics (so it's free on the request path), is **dependency-free** (no `rich`), and is dev-only — in production you'd scrape the metrics endpoint instead. See [Observability → Dev dashboard](guides/observability.md#dev-dashboard).
- **Structured access logging.** Opt into one structured log line per request — `method`, `path`, `status`, `duration_ms`, and the request's correlation id — via `observability.accessLog`, in `"console"` (human-readable) or `"json"` format. The correlation id is bound into a context variable for the request's duration, so your own log calls pick it up too. Works with **no new dependency** (a stdlib JSON/console formatter); the optional `[observability]` extra adds [structlog](https://www.structlog.org/) for richer rendering. Off by default so it won't disrupt an existing log pipeline. See [Observability → Structured logging](guides/observability.md#structured-logging).
- **Observability: request IDs, timing, metrics, and richer health probes.** Every request now gets a correlation id — surfaced as the `X-Request-Id` response header and on `request.state.request_id`, readable from any `@server` loader or `@action` — and its duration is measured, along with SSR-render, loader, action, and page-cache (hit/stale/miss) metrics. The request-id and timing are **on by default** (a `uuid4` and two `perf_counter` reads, no I/O, added at the outermost layer so even a CSRF rejection is tagged); an incoming `X-Request-Id` is **not** trusted unless you opt in (`observability.trustIncomingRequestId`), since echoing a client value into logs is a spoofing vector. Metrics are recorded into a bounded, allocation-cheap in-process registry and exposed — **opt-in** — at a Prometheus endpoint (`observability.metricsEndpoint`, optionally bearer-guarded); the page-cache hit ratio comes from the existing server cache. `/readyz` now runs **dependency checks** (today: the SSR worker pool has a live worker) and returns `503` until the server is genuinely ready, while `/healthz` stays a pure liveness probe. All configured under the new [`observability`](reference/configuration.md#observability) block (`"observability": false` disables request-id/timing); the helper `from pyxle.observability import get_request_id` reads the id anywhere. **Multi-worker note:** metrics are per-worker (each series carries a `worker` label) — aggregate at the scraper. Structured logging, a `pyxle dev` dashboard, and OpenTelemetry land next in Phase 2.7. See [Observability](guides/observability.md).
- **Typed request validation for `@action` with Pydantic.** An action can now declare a body parameter annotated with a [Pydantic](https://docs.pydantic.dev/) model — `async def register(request, body: Signup)` — and Pyxle parses, coerces, and validates the request body before the action runs, passing in a fully-typed instance. No more hand-written `await request.json()` + key-by-key checks. On failure the action is **not** called and the client gets a `422` with a top-level `fields` map (field path → messages, dotted for nested models and indexed for list items: `address.zip`, `tags.0`). Both `useAction` and `<Form>` surface it — `result.fields` / the reactive `submit.fields`, and `<Form onError={(message, fields) => …}>` — so you can render messages next to each input. For checks Pydantic can't express (uniqueness, cross-field rules) raise the new `ValidationActionError`, which is auto-imported alongside `ActionError` and produces the same `422` shape. Because the body models are real Pydantic models, `pyxle openapi` generates an [OpenAPI 3.1](https://spec.openapis.org/oas/v3.1.0) document of every action's request body straight from your code (`--out openapi.json`), derived from runtime introspection so it always matches what the dispatcher validates. Pydantic is an **optional dependency** — install the extra with `pip install "pyxle-framework[pydantic]"`; actions without a model parameter are unaffected, and an action that declares one without Pydantic installed fails with a clear error rather than silently skipping validation. The generated `useAction`/`Form` runtimes now also ship TypeScript declarations (`.d.ts`). See [Server Actions → Validating request bodies](core-concepts/server-actions.md#validating-request-bodies-with-pydantic).
- **Fix: a server module that fails to import is no longer cached as a broken empty module.** If a page's compiled server module raised during its first import (e.g. a bad top-level `import`), the half-initialised module was left in `sys.modules`, so every later request for that page silently got an *empty* module instead of re-raising the real error. Failed imports are now evicted, so the error surfaces consistently on each request.
- **WebSockets — page handlers, a client hook, and pub/sub.** A page `.pyxl` can now export a module-scope `async def websocket(ws)` and Pyxle serves a WebSocket route at the page's path, alongside its HTTP render — the same file handles both protocols, and dynamic segments (`pages/chat/[room].pyxl`) resolve into `ws.path_params`. Detection is by convention (the function name, not a decorator), matching how `pages/api/**` modules already expose a `websocket` callable. The new `pyxle.realtime` module ships a small pub/sub layer: `async with channel(ws, "room") as room: await room.publish(msg)` subscribes a connection to a named channel and broadcasts to everyone in it, with stale-connection pruning. Because Starlette runs HTTP middleware only for `http` scope, a WS handler gets **no** middleware — so `pyxle.realtime` also provides `authenticate_websocket(ws)` (resolve the pyxle-auth session from the handshake cookie) and `origin_allowed(ws, origins)` (the WS equivalent of CSRF). On the client, the generated `useWebSocket(path, options?)` hook gives `{ status, send, lastMessage, error }` with JSON parsing and exponential-backoff reconnect, and never opens a socket during SSR. **Multi-worker caveat (called out honestly):** the default in-process broker lives in one process, so under `pyxle serve --workers N` a message published on one worker isn't seen by clients on another — Pyxle logs a warning when it detects this, and the `Broker` protocol lets a Redis-backed broker drop in. See [WebSockets](guides/websockets.md).
- **Streaming SSR for `<Suspense>` pages.** A page that wraps a slow part in a React 18 `<Suspense>` boundary now streams: Pyxle flushes the shell (everything outside the boundary) immediately for a fast time-to-first-byte, then streams each boundary's content in as it resolves. It's opt-in and zero-config — the compiler detects `<Suspense>` and only those pages stream; every other page keeps the buffered render byte-for-byte. The page hydrates exactly as before (the browser hydrates the same component), so no app changes are needed beyond adding the boundary. Streaming applies to dynamic, per-request pages only: a publicly cacheable route (`{"data", "revalidate"}` envelope, `CACHE` directive, or edge `cache` entry) still renders buffered so it can be stored and `ETag`'d, and a streamed response is always `private, no-cache`. The document head is flushed before the component renders, so a streamed page uses its static `HEAD` (a runtime-rendered `<Head>` lands too late — buffered pages are unaffected). A render error before the first byte falls back to the nearest `error.pyxl` rather than emitting a partial document. Built on the Node worker's new multi-frame `renderToPipeableStream` transport. See [Streaming SSR](guides/streaming.md).
- **`loading.pyxl` route-level loading states.** A `loading.pyxl` file declares a loading component that wraps the whole route in `<Suspense fallback={<Loading/>}>` — streamed as the shell on the server and applied identically on the client so hydration matches. The nearest `loading.pyxl` wins (directory walk-up, like `error.pyxl`), and it composes with a page's own inner `<Suspense>`. Honest caveat: because the `@server` loader runs before render, the fallback only appears when the *render* suspends (a child using `React.lazy`, `use()`, or a thrown promise) — a page whose data comes entirely from its loader never suspends and streams at once. See [Streaming SSR → Route-level loading states](guides/streaming.md#route-level-loading-states-with-loadingpyxl).
- **Server-side page caching with incremental regeneration.** A `@server` loader can now return a `{"data": ..., "revalidate": N}` envelope to cache its rendered HTML for `N` seconds — later requests are served from the cache without re-running the loader or the Node SSR render. A loader-less page can opt in the same way with a module-level `CACHE = {"revalidate": N}` directive. And `pyxle build --static` pre-renders every loader-less, non-dynamic page to HTML at build time and warms the cache from it on startup, so the first request after a deploy is a hit — no cold render. Once the window passes, the stale page is served instantly while a single background re-render refreshes it (incremental static regeneration — no thundering herd). Purge a route on demand from an action with `await cache.invalidate("/path")` (or `cache.invalidate_all()`). Routes already declared in the `pyxle.config.json` edge `cache` block are server-cached automatically under the same TTL. Cached responses carry a strong `ETag` (so conditional requests get a `304`) and an `x-pyxle-cache: HIT|STALE|MISS` header. The cache is enabled for `pyxle serve` (off in `pyxle dev`) and stores to a bounded in-memory backend by default, or to local disk or a shared Redis via `PYXLE_PAGE_CACHE_BACKEND` (Redis needs `pip install 'pyxle-framework[redis]'`). Only cache pages that render no per-user data — a cached render is shared with every visitor. See [Caching](guides/caching.md).

## 0.4.5

- **Signed cookies & tokens — `sign_cookie` / `verify_cookie`.** New stdlib-only helpers (importable from `pyxle`) attach a tamper-proof HMAC-SHA256 signature to any string — a session id, a "remember me" token, a stateless unsubscribe or password-reset link — and verify it later in constant time. The secret comes from `PYXLE_SECRET_KEY` (or an explicit `secret_key=`), and a `salt=` namespaces signatures so a token minted for one purpose can't be replayed for another. Signing without a secret raises `MissingSecretKeyError` rather than returning an unprotected value — it fails closed. See [Security → Signed cookies and tokens](guides/security.md#signed-cookies-and-tokens).
- **Fix: `PYXLE_PUBLIC_*` client env vars now work in `pyxle dev` and no longer break `pyxle build`.** The generated Vite `define` emitted each value as a bare expression, so a non-identifier value (an API URL, a `0x…` Turnstile key) was silently dropped in dev and crashed `vite build` with esbuild's "Invalid define value". Values are now emitted as quoted JS string literals, so `import.meta.env.PYXLE_PUBLIC_*` resolves correctly in both dev and production builds. See [Environment variables → Client-side variables](guides/environment-variables.md).
- **Fix: web fonts and other CSS `url()` assets no longer 404 in `pyxle dev`.** Vite rewrites `@font-face`/`url(...)` references to root-relative `/@fs/…` paths, which the browser resolved against Pyxle's origin instead of Vite's and 404'd — so `@fontsource` `.woff2` files silently failed to load in development (production builds were unaffected, as their assets are hashed and served by Pyxle). Pyxle now sets Vite's `server.origin`, so dev assets load from Vite directly.

## 0.4.4

- **Fix: cross-page hash links scroll to their anchor.** Client-side navigation to `/page#section` changed the page but stayed pinned to the top (only the URL carried the hash); a full load scrolled correctly. The router now jumps to the top and then scrolls to the anchor as soon as the next page's DOM commits, matching native behaviour — including for unknown anchors, which stay at the top.

## 0.4.3

- **Security: hardened HEAD sanitisation (XSS).** Dynamic `HEAD` values/callables that interpolate loader data into raw head strings — the documented dynamic-meta-tags recipe — could previously inject markup because attribute values weren't escaped (a `"` in a `<meta content>` broke out of the attribute). Head elements are now parsed and rebuilt from a strict tag allowlist with every attribute value HTML-escaped, `on*` handlers dropped, `javascript:`/`vbscript:`/`data:` URLs neutralised, `<meta http-equiv="refresh">` and non-head tags rejected, and any markup injected after a breakout discarded. Inline `<script>`/`<style>` head content remains supported as trusted author code. Self-closing head tags now serialise canonically as `/>`.
- **Security: CSRF exempt paths match on segment boundaries.** `csrf.exemptPaths` previously used a bare string prefix, so exempting `/api/webhooks` also exempted an adjacently-named sibling like `/api/webhooks-admin`. Exemptions now match a path exactly or at a `/` boundary.
- **Security: oversized no-JS form POSTs fail loud.** A form-encoded POST whose body exceeded the CSRF buffer cap (1 MB) was silently truncated and replayed to your handler. Such requests now return `413` and ask for the token via the `X-CSRF-Token` header instead of corrupting the payload.
- **Fix: `<Script>`/`<Image>` boolean attributes written as strings.** `defer="false"`, `async="no"`, `priority="0"`, `lazy="false"` and similar quoted-falsy forms were coerced to `True` (the opposite of the source). They now coerce correctly.
- **Fix: custom `csrf.cookieName` / `csrf.headerName` now reach the client runtime.** Configuring either name made every action POST fail with `403` — the middleware set and validated the cookie under the configured name while `useAction`/`<Form>` kept reading a literal `pyxle-csrf` cookie and sending a literal `x-csrf-token` header. Non-default names are now injected into the document shell as `window.__PYXLE_CSRF_COOKIE__` / `window.__PYXLE_CSRF_HEADER__` and the client runtime resolves them with the defaults as fallback, in both dev and production builds.
- **Fix: no double loader run on hover-then-click navigation.** When a `<Link>` was prefetched on hover/viewport and then clicked, the click raced a second request and ran the page's `@server` loader twice. The click now reuses the in-flight prefetch, and a navigation-sequence token discards a superseded prefetch so a slow one can't render a stale page over a newer click.
- **Multi-core serving: `pyxle serve --workers N`.** Production serving can now run N independent server processes on one port (each with its own SSR pool and event loop) — throughput scales with cores, no load balancer or shared state to configure. See [Deployment → Multi-core (worker processes)](guides/deployment.md#multi-core-worker-processes).
- **Sync API endpoints.** A plain `def endpoint(request)` in `pages/api/` now runs in Starlette's threadpool instead of failing at request time — blocking database drivers and sync SDKs no longer require manual `asyncio.to_thread` wrapping. Sync `get`/`post`/… methods on `HTTPEndpoint` classes are threadpooled too, and `HTTPEndpoint` classes dispatch correctly alongside route hooks. See [API Routes → Sync endpoints and blocking calls](guides/api-routes.md#sync-endpoints-and-blocking-calls).
- **In-memory static asset cache.** When serving a production build, small static files (≤1 MB each, 32 MB total per process) are loaded into memory at startup and served without filesystem I/O or threadpool hops — several-fold higher static throughput. Conditional requests (`ETag`/`If-Modified-Since` → 304) and cache headers behave exactly as before; larger files keep streaming from disk.

## 0.4.2

- **Live dev-server reconciliation.** Editing a `.pyxl` in `pyxle dev` now applies route-*shape* changes without a restart — rename/add/remove a `@server` loader or `@action`, add or delete a page, wrap a page in a layout, change the head. The route table is rebuilt and hot-swapped on every change (these previously needed `rm -rf .pyxle-build` + a restart). Editing `pyxle.config.json` prints a clear "restart to apply" warning instead of being silently ignored.
- **`pyxle check` works on a clean install.** The JSX checker's parser dependencies are bundled into a self-contained extractor (shipped via `pyxle-langkit`), so `pyxle check` runs after `pip install 'pyxle-framework[langkit]'` with no extra npm setup. A missing-dependency failure now names the exact packages instead of an opaque error.
- **Locale-independent SSR.** The Python↔Node SSR transport pins UTF-8, so emoji and other non-BMP characters in components or loader data no longer crash rendering under a non-UTF-8 locale (e.g. `LANG=C`).
- **Smoother first run.** `pyxle init` generates a gitignored `.env.local` with a random dev `PYXLE_SECRET_KEY` (CSRF HMAC on out of the box); the scaffold `requirements.txt` now declares `pyxle-framework` itself; and `pyxle install` warns about PEP 668 externally-managed environments with venv guidance instead of letting pip throw a raw wall.
- **Docs:** documented calling an `@action` endpoint directly for scripts and tests.

## 0.4.1

- **No more double loader run on first load.** The page you land on is now seeded into the client navigation cache from the server render, so the active nav link's prefetch (a `<Link>` pointing at the current route) resolves from cache instead of re-fetching. The loader runs **once**, not twice — halving origin work on cold loads and stopping non-idempotent loaders (view counters, analytics) from firing twice. Back/forward navigation to the page is instant for the same reason.
- **Per-route navigation-cache TTL.** A route's [`cache`](reference/configuration.md#edge-caching) TTL now also governs how long its prefetched/seeded data stays fresh in the client navigation cache, so client freshness matches how long a CDN would serve the page. Routes without a `cache` entry use a default of **2 minutes** (raised from 30s), tunable via the new [`navigation.defaultPrefetchTtl`](reference/configuration.md#navigation) option.

## 0.4.0

- **Edge caching.** Declare cacheable routes in [`pyxle.config.json::cache`](reference/configuration.md#edge-caching) and pages are served `Cache-Control: public, s-maxage=N` (plus `stale-while-revalidate`) so a CDN or reverse proxy can absorb traffic instead of your origin — Pyxle's config-driven take on per-route revalidation. The per-user CSRF cookie is automatically omitted from cacheable responses. See [Deployment → CDN and edge caching](guides/deployment.md#cdn-and-edge-caching).
- **Hardened production errors.** SSR render failures — including the SPA-navigation JSON path — are sanitized in the response (no exception type, message, or path leaks to the client) while the full error is written to the server log for operators.
- **Faster static serving.** The static-asset middleware indexes public/client paths up front, skipping a per-request filesystem `stat` + exception on every dynamic request.
- **Layout & template loaders.** A `layout.pyxl` or `template.pyxl` can declare its own `@server` loader; its result lands on the component's `data` prop, just like a page — so shared UI (nav bars, the signed-in user, the framework version) loads once per request without repeating the loader in every page. See [Layouts → Layout data loaders](core-concepts/layouts.md#layout-data-loaders).

## 0.3.0

- **First-class plugin system.** Compose apps via `pyxle.config.json::plugins` (Django-style `INSTALLED_APPS`) — see the [Plugins guide](guides/plugins.md) and [Plugins API reference](reference/plugins-api.md).
- **Django-style service access.** Resolve any plugin-registered service with `from pyxle.plugins import plugin` and `plugin("auth.service")`, or use a typed shortcut shipped by the plugin (e.g. `from pyxle_auth import get_auth_service`).
- **First-party plugins.** Two official plugins land: [`pyxle-db`](plugins/pyxle-db.md) (SQLite-first with migrations) and [`pyxle-auth`](plugins/pyxle-auth.md) (email+password sessions, argon2id, rate limits).
- **WebSocket endpoints** — `pages/api/*.py` can export `async def websocket(ws)` for live updates, chat, log streaming. See the [API Routes guide](guides/api-routes.md#websocket-endpoints).
- **Client navigation cache with TTL + invalidation.** Loader payloads are cached for 30s by default (tunable) so back/forward navigation is instant. Call [`invalidate(url)`](reference/client-api.md#invalidateurl) from the client or return [`invalidate_routes(response, ...)`](reference/runtime-api.md#invalidate_routesresponse-urls) from an `@action` to keep list views fresh after mutations — automatically honoured by `useAction` and `<Form>`.
- **`ActionError` is auto-imported** for any `.pyxl` with an `@action`. No more `NameError: name 'ActionError' is not defined` on first try.
- **`<Head>` coerces multi-part `<title>` children** into a single string, silencing React's "title element received an array" warning for the common `<title>{name} — Brand</title>` pattern.
- **SSR worker pins `LANG=en-US.UTF-8`** by default (override with `PYXLE_SSR_LOCALE`) so `toLocaleString()` and other Intl calls stop causing hydration mismatches.
- **Vite resolver prefers pinned versions.** `pyxle build` now runs `npm install` before falling back to `npx --yes vite`, so builds honour your `package.json` pin instead of fetching `vite@latest`.
